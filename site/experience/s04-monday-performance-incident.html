Since Sprint 02 the company sales model carries both the Sales and the ledger definitions. It now has 31 million order lines from 2023 onwards, and the executive page has gained a few visuals.

Why the business cares Eight executives wait for the page at the start of every leadership meeting, and some have started asking for Excel exports instead. A slow report is an abandoned report, and the capacity is busiest exactly then.

What you are expected to do

  • Establish a baseline: which visuals cost the most, and is each one formula-engine bound or storage-engine bound?
  • Find the root cause of each slow visual, with evidence from the files.
  • Rewrite or remodel so the page is fast without changing any number on it.
  • Measure again and produce a before/after table: Visual | Before | After | Improvement | Root cause.
  • Propose a performance budget for this page, and explain to Elena whether a bigger capacity is the answer.
  • Write two versions of the result: one for Grace, one for the engineers.

Deliverables

  • Baseline: per-visual timings and FE/SE split
  • Root cause per slow visual, with the evidence line that proves it
  • Optimised measures and model changes (DAX/TMDL)
  • Before/after table with improvement %
  • Regression check: every visual returns the same values as before
  • Executive note and engineering note (same facts, two audiences)

Evidence

  • performance_analyzer.json Performance Analyzer export of the executive page, cold cache, Monday 08:55.
  • server_timings.csv DAX Studio Server Timings for the four slowest visuals' queries.
  • vertipaq_columns.csv VertiPaq Analyzer: column sizes and cardinality.
  • measures.dax The measures on the page, as they are today.
  • model_notes.md
  • Reproduce it on your machine (optional)
