Review checklist for the release train

  • Both changes kept unless one is wrong.
  • No broken references in measures or in report visuals.
  • BPA: no new errors (severity 3); warnings explained.
  • PR description: what changed, why, how it was tested, risk, rollback.

Net Revenue name

Just so you know: in the KPI dictionary "Net Revenue (ledger)" is the Finance measure. I asked Sam to rename the order-based one, but I didn't mean to call it plain "Net Revenue"! Can we make sure the names don't clash?

What you are expected to do

  • Work out what each branch changed relative to the common ancestor (a three-way comparison, not two files side by side).
  • Resolve the conflict so both intentions survive, and so no measure or visual references a name that no longer exists.
  • Validate: the file must open in Power BI Desktop (or parse in Tabular Editor), every measure must evaluate, and BPA must show no new errors.
  • Commit with a meaningful message and write the pull request description, including risk and rollback.

Deliverables

  • Resolved _Measures.tmdl
  • List of every reference you had to update (measures and report visuals)
  • BPA result after the merge, with each remaining warning explained
  • Pull request description

Evidence

  • git_log.txt Branch graph, the failed merge, and where the report uses the measure.
  • base/_Measures.tmdl (common ancestor)
  • ours/_Measures.tmdl (your branch)
  • theirs/_Measures.tmdl (Sam's branch)
  • conflicted/_Measures.tmdl (what Git left you)
  • bpa_results.json (on your branch, before merging)
